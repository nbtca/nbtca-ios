# 拔电关机 · NBTCA iOS

参照 `Android/nbtca-app/frontend/lib` 移植的原生 SwiftUI 客户端，最低支持 iOS 18，无第三方 Swift 依赖。Android 源码和 Go BFF 保持原样。

## 已实现

- **拔电关机**：资讯列表、可左右滑动的分类分页、搜索、文章详情、Markdown 内容、官网原文与系统分享；启动时先显示已缓存资讯及保存时间，再获取新内容；正文按服务器与文章分别缓存，重复打开可直接阅读，并可手动更新。
- **维修**：预约、AI 预检、我的记录、状态筛选、分页、详情、编辑与取消；技术员接单、放弃、现场照片上传、提交与修改报告；管理员审核结单与退回检修。
- **工具**：协会活动日历、日历订阅入口、协会文档、服务分组、异常组件和服务事件。
- **教务查询**：学校统一身份认证、学期选择、星期 × 节次网格课表（默认本周、单双周和实践课）、导出到苹果日历、考试安排、成绩与绩点查询；校园网与 WebVPN 自动选择。
- **寝室文明查询**：同一次检查中并列展示宿舍、个人和总分，详情按学校页面分为三个区域，保留各自备注和扣分说明；按学年和学期筛选，搜索检查日期、寝室及分数，iPad 自适应双列。
- **个人中心**：Logto 登录/注册、钥匙串存储、自动刷新凭证、退出登录、基于真实角色切换界面视角、外观与 BFF 地址持久化。

资讯、日历、服务状态与预检请求 BFF；维修业务直连 `https://api.nbtca.space/v2`。BFF 请求不携带维修访问凭证。未登录不请求公开工单队列，不提供模拟管理员账号。

## 运行

1. 用 Xcode 打开 `nbtca.xcodeproj`，选择 `nbtca` scheme 和已连接的 iPhone；真机运行需配置自己的开发团队和签名。
2. Debug 与 Release 均默认连接 `https://bff.nbtca.space/api/v1`，与 Android 正式包发布配置一致，无需在本机启动后端。App「个人中心 → 后端服务器」中已保存的自定义地址优先使用。
3. 如需调试自己的 BFF，可启动参考工程中的服务：

   ```sh
   cd Android/nbtca-app/backend
   go run ./cmd/server
   ```

   在 App 中配置完整 API 地址；真机连接本机服务时使用电脑的局域网地址，首次连接时允许 App 的本地网络访问。

仅 Debug 构建通过 `Config/Debug.plist` 允许 HTTP 调试。Release 自定义后端需使用 HTTPS；也可在构建时设置 `INFOPLIST_KEY_NBTCAAPIBaseURL=https://你的服务器/api/v1`，覆盖首次启动的默认值。

## 文章阅读

- 详情页优先读取原文 `https://nbtca.space/posts/...` 的 `article.article .prose`，保留段落、表格、代码高亮、图片与版权署名；不重复显示原站导航和页头。原站不可达或没有识别到正文容器时，显示接口 `content_markdown`，不猜测接口已经丢失的表格结构。
- 使用单个隔离的 WKWebView 排版，正文可选择复制；图片按比例缩放，代码及表格在各自区域横向滚动，目录链接在文章内跳转。适配深浅色、系统字号、iPhone 与 iPad 宽度，不运行原网页脚本，也不共享登录 Cookie。
- Markdown 解析器 markdown-it 15.0.3 与 DOMPurify 3.4.17 随 App 打包，不依赖运行时 CDN。正文经过净化，保留代码颜色但移除原站布局样式；原始内容通过 Base64 JSON 传给本地渲染器，不拼接进可执行脚本。版本和许可证位于 `nbtca/Resources/ArticleReader/ThirdPartyNotices.txt`。
- 渲染测试：临时目录安装 `jsdom@26.1.0` 后，以 `NODE_PATH=该目录/node_modules node --test Scripts/test-article-reader.cjs` 运行；可设置 `NBTCA_REFERENCE_ARTICLE` 指向原网页 HTML，额外核对真实正文。`Scripts/test-academic.py` 同时包含原文请求与后备行为的 Swift 测试，不启动模拟器。

## 教务查询与网络切换

入口：工具 → 教务服务（课表、考试、成绩）；个人中心也提供教务入口。使用学校统一身份认证账号，与 NBTCA Logto 登录相互独立。

首次查询等待登录校验与学期加载完成；即使学校恢复的学期和本地课表相同，也会触发考试、成绩查询。只有当前类别、学期的请求成功完成后才显示结果或空状态，加载前不将空数组误报为“暂无考试安排”。切换学期或类别后，旧请求的返回值不会覆盖当前查询。

实现参考 [nbtca/Prompt](https://github.com/nbtca/Prompt) 及其依赖 [nbtca/nbtcal](https://github.com/nbtca/nbtcal) 的 0.4.5 查询协议。上游 MIT 许可与版本记录见 `nbtca/Resources/AcademicNotices.txt`，该文件随 App 打包。

- 内网教务：`https://jwxt.nbt.edu.cn`；外网教务：`https://jwxt-443.webvpn.nbt.edu.cn`，通过 `https://webvpn.nbt.edu.cn` 登录。
- 自动模式通过系统网络路径监听和不携带会话的 HTTPS 内网探测选择线路。Wi-Fi / 有线连接时验证教务服务的登录指纹或可信 CAS 跳转，拒绝把普通路由器页面、强制门户和 WebVPN 页面误判为校园网；内网不可达或使用蜂窝网络时选 WebVPN。
- 不依赖 SSID，因此 NITWLAN、NITWLAN-Auto 和校内自接路由器只要能实际访问内网教务即可直连。无需为读取 Wi-Fi 名称索取定位权限。网络变化、回到前台及手动重检会触发检测；界面也提供自动、内网、WebVPN 三种选择。
- 若 iOS 提示本地网络访问，请允许访问；未允许、学校服务故障或网络未认证导致直连探测失败时会选用 WebVPN，也可手动重试。
- 使用学校官方 WKWebView 登录页面，由用户完成密码、验证码或二次认证。App 不读取和保存教务密码，不自动破解或跳过验证，不忽略 TLS 证书错误。
- 两条线路使用隔离的非持久 WebKit / URLSession 会话，验证成功后将 Cookie 分别保存在本机钥匙串（仅本设备、解锁时可用，不同步 iCloud）。同一线路的教务与寝室查询共用 WebKit 数据存储及 HTTP Cookie 容器，并保持各 Cookie 的域名和路径。重启后读取已有钥匙串条目并合并到共用会话，自动通过 CAS 建立所需服务会话；保留 Cookie 原始有效期，本地最长保留 7 天。临时断网不删除登录状态，退出学校登录时统一清除教务、学工在两条线路上的钥匙串及内存会话。
- 查询成功后，将解析后的课表按学期保存在本地 Application Support，使用 iOS 文件保护并排除系统备份，不保存原始响应、密码或学号。退出学校登录或重新完成交互登录时清除本地课表。考试、成绩、寝室查询结果仍只在内存中处理，进入后台时清除。不打印个人原始响应。用户主动导出课表并授予系统日历权限后，才将课程写入苹果日历；另保存导出目标和日程的系统标识以便更新。
- 登录页显示加载中的学校主机，35 秒未完成时给出重试入口；连接错误显示主机和错误码，不输出含 CAS 票据的 URL、密码或 Cookie。页面进程退出时提示重新加载，允许切换 WebVPN。DOM 检查只处理当前已完成导航，不打断后续认证跳转，也不从未知错误页自动查询。
- 查询限定于上游的只读路径，校验学期及完整分页。考试未公布日期、实践课未排定节次、缺少学校节次时间时明确展示原始状态，不推算时间。

### 课表与日历导出

- 课表按星期和节次显示，跨节课程合并为一个区块，重叠课程并排显示；iPhone 保留一周七列，iPad 使用窗口宽度自适应。点按课程查看完整信息。
- 重新打开 App 时先显示本地课表，离线也可查看；联网查询成功后更新本地记录。首页在下一节课开始前 30 分钟显示课程名、时间及教室，点按进入课表，开始上课后隐藏；只读取本地课表，不触发资讯刷新。提醒使用学校日期、周次和节次时间，缺少这些信息时不猜测上课时间。
- 首次查询、再次进入课表和回到前台时自动选择本周；提供“本周”按钮。周次以教务日期为先，缺少日期时读取 Prompt 使用的 `https://ical.nbtca.space/school.ics`，按学年及学期匹配开课日期，并校验与教务日期一致。按上海时区计算，周一切周，周末不会回到第一周。未取得校历时明确显示不可用，不按月份猜开学日期。
- “导出到苹果日历”先展示整学期的日程数量和无法导出的课程，再由用户授权并写入系统日历。按单双周展开为独立日程，使用学校返回的节次时间，保存教师、教室；不把未排定的实践课编造成全天日程。日期缺失、时间缺失或冲突的安排会列出并跳过。
- 每学期创建独立课表日历，记录系统日程标识；先由用户授权检查，再展示新增、更新和失效日程的明细，确认后写入。调课按新增与旧日程失效展示，教室变更更新原日程。用户可选择清理失效日程，仅处理本 App 记录的目标日历与日程标识；存在无法完整导出的课程时禁用清理，避免误删。整学期课程全部取消时也能检查并清理。批量写入与清理一次提交，失败时丢弃未提交修改。权限说明同时配置在 Debug / Release 的生成 Info.plist 中。

无需模拟器即可运行教务协议测试（不连接真实教务，不使用个人账号，最多两个编译任务）：

```sh
python3 Scripts/test-academic.py
```

真实 CAS/WebVPN 登录、校园内网/自接路由器自动切换与个人查询需要在实际网络和学校账号下联调。首次实现已做模拟协议测试和真机目标编译，不代表已完成学校真实账号验证。

### 寝室文明查询

入口：工具 → 寝室文明查询；个人中心 → 学校服务也提供入口。该功能实际来自学工系统，不使用教务成绩接口。对照学校登录后的宿舍文明页面、页面脚本及只读网络请求确认协议：

- 直连页面：`https://xsgl.nbt.edu.cn/xsfw/sys/sswsapp/*default/index.do?THEME=indigo#/dorm_health_student`。
- 宿舍卫生：POST `/xsfw/sys/sswsapp/modules/dorm_health_student/sswsxs_sswsxsbg.do`；个人卫生：POST `/xsfw/sys/sswsapp/modules/person_health_student/grwsxs_grwsxsbg.do`。
- 使用 `pageSize`、`pageNumber` 分页，解析 `datas.<action>.rows/totalSize/pageNumber/pageSize`。由学校服务端依据登录账号限制可见记录；客户端不提供任意学号或寝室越权查询。完整分页后再展示，拒绝重复或不完整页，不输出个人原始响应。
- 展示检查日期、楼幢与寝室、检查类型、周次、分数、备注及扣分说明。学工 `XQ=1/2` 与教务 `xqm=3/12` 分开处理，筛选使用返回的学年、学期代码与名称。检查图片通过学校原始页面查看，客户端不保存附件令牌。
- 对照已登录的学校个人查询表头和接口字段：`DZ_GGFS` 为公共（宿舍）卫生分数，`DZ_GRFS` 为个人卫生分数，`JCFS` 为总分数；宿舍记录自身的分数使用 `FS`。三项分数原样展示，不将个人记录的 `FS` 当总分，不通过求平均补出总分，空值显示“未公布”，零分仍显示为零。
- 每次查询完整读取个人和宿舍两类记录。使用学校返回的检查编码 `JCBM`、宿舍标识 `SSDM`，并核对学年、学期、日期、检查类型、周次，唯一匹配后关联宿舍备注和违规类型。个人记录保留自己的扣分说明及总分备注；关联字段缺失、冲突或有歧义时分开展示，不按日期猜测匹配。点按记录，按“宿舍检查情况”“个人检查情况”“总分”查看圆形得分与说明。资料仍只在内存中处理，进入后台时关闭详情并清除查询记录。
- 学工与教务共用同一线路的学校登录状态，双向复用 CAS / WebVPN Cookie；各服务 Cookie 仍按原域名和路径发送，绝不把教务 JSESSIONID 改域为学工 Cookie。打开另一项服务时自动完成 CAS 跳转，统一认证仍有效时无需单独登录；查询发现服务会话失效会自动尝试恢复一次。退出学校登录时统一清除。旧版教务、学工钥匙串条目都会合并恢复。
- 登录校验等待学工表格实际初始化，初始化中的缺失数据集最多重试 3 次。接口校验失败会保留学校网页，显示具体失败类别，可继续操作学校页面或点“继续查询”，不销毁浏览器重新要求登录。学工请求通过已认证 WKWebView 的同源 fetch 发出，使用与官方 SPA 一致的 Cookie、Origin、Referer 及 WebVPN 上下文；分页兼容整数或整数字符串，缺少回显页码时使用已发送的页码，仍校验总数、重复记录与完整分页。WebVPN 返回过渡网页、缺少数据集、分页异常和记录异常分别提示，不打印原始响应。
- 外网使用 `https://xsgl-443.webvpn.nbt.edu.cn` 的同一路径。未登录的 WebVPN 请求会先要求更新站点密钥，不能凭匿名响应中的 `site not found` 判断站点是否已配置；完整外网登录与映射可用性仍需实际网络联调。直连已通过用户打开的学校页面核对，App 内查询尚需设备验证。

新增测试使用虚构的寝室、记录及 Cookie，覆盖学工独立域名、旧会话兼容、字段映射、空分数与零分、两类查询路径、完整分页、重复页和登录失效。不会将真实学生资料写入测试文件。

## iPad 与多窗口

- 主导航采用系统可展开侧边栏的 TabView；首页保留左右滑动切换资讯分类。每次 App 进程启动后首次进入首页加载一次，返回首页时复用已有内容；使用右上角“刷新”按钮手动更新，失败后也不因再次进入页面自动重试。切换后端地址会单独加载新服务器的内容。
- 根据当前窗口可用宽度布局，不依赖屏幕尺寸或设备型号。窗口宽度达到 760 pt 时，资讯、工单、服务分组和活动卡片使用双列，内容区域最大 1120 pt；较窄分屏自动恢复单列。
- 辅助功能大字体使用单列，正文与个人中心保持适合阅读的宽度，表单限制为 720 pt。
- 设置、报修和维修报告使用系统表单弹窗；登录使用页面弹窗，随窗口和键盘调整。
- 工程支持 iPad 横竖屏和分屏。布局变更仅做真机目标编译检查，不启动模拟器。

## 维修与草稿

- 维修状态筛选统一处理 `pending/open`、`repairing/accepted`、`completed/closed`、`canceled/cancelled`。列表标注已加载数量；分页尚未结束时，不将当前没有匹配误报为全部记录为空。
- 同一账号及工单范围刷新时保留旧记录，成功后整体替换；失败保留内容与分页位置。切换账号或范围立即清空，旧请求不能覆盖新范围。服务状态刷新同样保留上次内容，切换后端时清空。
- 报告照片通过 ImageIO 在后台直接生成最长边 2000 像素的上传图与 160 像素预览图，修正方向，避免先解码整张原图；支持上传进度与失败重试。照片已经上传、报告提交失败时，只重试报告。
- 报修新建、编辑与报告分别自动保存文字草稿，按 NBTCA 账号和工单隔离。再次打开恢复文字，提交成功清除，退出 NBTCA 登录统一清除。草稿采用 iOS 文件保护并排除系统备份，不保存照片；关闭有改动的表单时可选择保存、放弃或继续填写，恢复报告时会提示重新选择照片。
- 每个教务、寝室查询页面拥有独立查询条件、任务与内存记录；不同窗口共享学校登录及课表缓存，关闭或后台清理一个页面不影响其他页面。学校换号与退出通过统一会话管理器同步使所有页面的旧结果失效。

## 登录与权限

沿用 Android 版的 Logto endpoint、公开客户端 ID、scope 和已注册回调 `https://nbtca.space/callback`。使用隔离的 WKWebView 完成 Authorization Code + PKCE，通过严格匹配回调地址及 state 获取授权码，在本机经 HTTPS 换取凭证。凭证保存在设备钥匙串，不写入 UserDefaults 或日志。

身份通过 `/oidc/me` 验证，Saturday `/member` 补充维修角色。界面视角只能降到账号拥有的权限，最终操作由 Saturday 服务端授权。iOS 版要求成功验证身份，不使用未验证 JWT 的本地解码内容作为登录身份。

## 验证

无需启动模拟器即可编译检查，以下命令限制为两个并行编译任务：

```sh
xcodebuild -jobs 2 -project nbtca.xcodeproj -scheme nbtca \
  -configuration Release -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO build
```

现有单元测试可按需在连接的测试设备上运行，不必启动模拟器。测试使用 URLProtocol 模拟响应，不写入真实工单。覆盖 Saturday 字段兼容、角色识别、日历时区、资讯去重、服务异常、RFC 7636 PKCE 向量、URL 校验、BFF 包装响应、HTTP 错误、路径编码、工单操作路由、照片 multipart 协议与空响应。

真实 Logto 登录、令牌刷新和维修业务的完整联调，需要有效 NBTCA 账号及对应技术员/管理员权限。无签名 Release 构建仅用于编译验证，不能直接安装到真机。
